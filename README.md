# ubersdr-packet

AX.25 packet radio decoder addon for [UberSDR](https://ubersdr.org) — connects to a remote UberSDR instance, tunes any number of channels simultaneously, and decodes AX.25 packet frames (including APRS) using [QtSoundModem](https://github.com/wb2osz/direwolf) with a live web UI.

---

## How it works

```
UberSDR (remote SDR) --► ubersdr-packet (Go) --► QtSoundModem (AX.25 decoder)
                                 |                        |
                                 └──► web UI              └──► decoded frames via SSE
                                      http://<host>:6089
```

- **`ubersdr-packet`** — Go service that connects to UberSDR via WebSocket, streams demodulated mono PCM audio per channel, and pipes it into a dedicated QtSoundModem subprocess
- **QtSoundModem** — decodes AX.25 frames (AFSK 1200, G3RUH 9600, etc.) from the audio stream; each channel runs 4 modem sub-channels (A/B/C/D) for simultaneous multi-modem decoding
- **Web UI** — live decoded frame display with APRS parsing, monitor/log panels, waterfall, and per-channel modem configuration; served on port 6089
- **SSE fan-out** — all connected browsers receive live frames simultaneously; late-joining browsers receive a replay of recent frames immediately on connect

Channels are managed entirely through the web UI and persisted to `channels.json` — no restart required to add or remove a channel.

## Quick start (Docker — recommended)

```bash
curl -fsSL https://raw.githubusercontent.com/madpsy/ubersdr_packet/main/install.sh | bash
```

This will:
1. Create `~/ubersdr/packet/` and download `docker-compose.yml` and helper scripts
2. Generate a random UI password and inject it into `docker-compose.yml`
3. Create the `data/` directory
4. Pull the latest `madpsy/ubersdr-packet` image
5. Start the service

Then edit `~/ubersdr/packet/docker-compose.yml` to set your UberSDR URL, and run `./restart.sh`.

Open `http://<host>:6089` to access the web UI.

## UberSDR proxy configuration

After installation, `ubersdr-packet` can be added as an UberSDR Proxy via the Admin interface:

| Field | Value |
|-------|-------|
| Name | `packet` |
| Host | `ubersdr-packet` |
| Port | `6089` |
| Enabled | `true` |
| Strip prefix | `true` |
| Rewrite websocket | `false` |
| Rate Limit | `250` |

## Configuration

All configuration is via environment variables in `docker-compose.yml`:

| Variable | Default | Description |
|----------|---------|-------------|
| `UBERSDR_URL` | _(required)_ | UberSDR WebSocket URL (e.g. `ws://ubersdr:8080/ws`) |
| `UBERSDR_PASS` | _(empty)_ | UberSDR bypass password |
| `UI_PASSWORD` | _(empty)_ | Password for write actions in the web UI (auto-generated by `install.sh`) |
| `DATA_DIR` | `/data` | Directory for `channels.json` inside the container |
| `WEB_PORT` | `6089` | Web UI port |
| `REPLAY_BUF_SIZE` | `200` | Recent AX.25 frames buffered per channel for late-joining browsers; `0` to disable |

Channels are **not** configured via environment variables — they are added and removed through the web UI and persisted to `channels.json`.

## Web UI

Open `http://<host>:6089` in a browser to access:

- **Channel list** — live status for every active channel: frequency, mode, connection state, DCD indicators per modem sub-channel
- **Decoded frames** — live AX.25 frame display with APRS parsing, callsign/destination/digipeater path, frame type badges, payload linkification, and callsign/type filters
- **Monitor panel** — raw KISS monitor output per modem sub-channel with TX/RX direction indicators
- **Log panel** — QtSoundModem process log output
- **Waterfall** — real-time audio spectrum display per channel
- **Modem configuration** — per-channel modem type, receiver count, FX.25/IL2P settings for each of the 4 sub-channels (A/B/C/D)

---

## Modem sub-channels

Each audio channel runs QtSoundModem with 4 independent modem sub-channels (A, B, C, D). Each sub-channel can be independently configured with:

- **Modem type** — AFSK 1200, G3RUH 9600, AFSK 300, etc.
- **Receiver count** — number of parallel receivers (1–6)
- **FX.25** — forward error correction (off / TX+RX / RX only)
- **IL2P** — improved layer 2 protocol (off / normal / legacy)

Sub-channels can be enabled or disabled independently. Configuration changes take effect immediately without restarting the channel.

---

## Audio

- **Sample rate**: always 12 000 Hz (UberSDR USB/LSB output)
- **Format**: mono S16LE PCM
- **Modes**: USB and LSB only (packet radio convention)

## Building from source

### Docker image

```bash
./docker.sh build          # build madpsy/ubersdr-packet:latest
./docker.sh push           # build and push to Docker Hub
./docker.sh run            # run locally (uses env vars)
```

Override the image name:
```bash
IMAGE=myrepo/ubersdr-packet:dev ./docker.sh build
```

### Go binary

Requires Go 1.21+

```bash
go build -o ubersdr-packet ./...
./ubersdr-packet \
    -url ws://sdr.example.com/ws \
    -listen :6089 \
    -data ./data
```

All flags:

| Flag | Default | Description |
|------|---------|-------------|
| `-url` | _(required)_ | UberSDR WebSocket URL |
| `-password` | _(empty)_ | UberSDR bypass password |
| `-listen` | `:6089` | HTTP listen address |
| `-data` | `./data` | Directory for `channels.json` |
| `-ui-password` | _(empty)_ | Password for write actions in the web UI |
| `-replay-buf` | `200` | SSE replay buffer size per channel (0 to disable) |

## Ports

The service listens on port `6089` inside the container and is accessible by container name on the shared Docker network (`ubersdr_sdr-network`). No host port mapping is needed — access is via the UberSDR proxy.

To expose the UI directly to the host for development, add to `docker-compose.yml`:
```yaml
ports:
  - "6089:6089"
```
